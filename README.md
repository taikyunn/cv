#### IdPのマスター情報をサービスへ反映するデータ同期基盤

**【プロジェクト概要】**

IdPのマスター情報を連携先サービスへ同期する基盤を開発しました。従来は、ユーザー情報を更新しても特定の操作を経た場合にのみサービス側へ反映されていました。IdPからWebhookで更新を通知し、サービス側がIdPのAPIから最新情報を取得する構成を採用し、本番提供しました。

**【担当範囲】**

要件調整・設計・実装・運用を主担当として推進。連携先の開発チームと仕様を調整し、所属チームのレビューを受けながら開発しました。

**【発揮したバリュー】**

- 連携先は1サービスで追加の見通しもなかったため、SCIMの実装は必要以上の対応になると判断し、必要な連携範囲を満たすWebhook方式を採用しました。
- 「リアルタイムに反映したい」という要求を、画面の再読み込み時に更新内容を確認できればよい、という要件に具体化しました。
- IdP側が更新通知、サービス側が最新情報の取得を担う設計を提案・実装。チーム間の責任境界を整理し、不具合発生時に担当を判断しやすい構成としました。
- ログの共通化と失敗時の通知を実装し、運用時に処理状況を確認できるようにしました。
- 本番提供を通じて、事業上重要な顧客のサービス導入に貢献しました。

#### ログイン時の操作負担を改善するパスキー認証

**【プロジェクト概要】**

顧客要件により、ログインのたびにパスワードとTOTPコードの入力が必要でした。パスワード入力に加えてスマートフォンで認証コードを確認する負担を課題と捉え、パスキー認証の追加を起案しました。

パスキー利用時はID・パスワードとTOTPコードの入力を省略し、利用が難しいユーザーには従来のID・パスワード＋TOTPも選択できる構成としました。認証方式は顧客と確認済みで、実装・テストを完了。本番提供は事業上の優先順位により待機中です。

**【担当範囲】**

導入の起案、対応デバイス・設定パラメーターなどの設計検討、チーム向け勉強会の主催。実装主担当が設計・実装・テストを進め、チームで設計検討とレビューを行いました。

**【発揮したバリュー】**

- パスワード入力・端末切り替え・認証コード入力という一連の操作に着目し、利用者の負担を減らす認証方式を提案しました。
- パスキーによる方式で顧客の二要素認証要件を満たせることを顧客と確認し、操作性と認証要件の両立を図りました。
- 従来方式も選択可能とし、ユーザーの利用環境の違いに対応しました。
- 勉強会を主催し、チームで実装を進めるための知識共有を行いました。
